# Global Plan sessions

Plan's scope picker includes Global and remembers either Global or the last project. New sessions send `projectId: null` for Global; the API also treats an omitted projectId as Global. Existing project IDs and message history are unchanged by migration 0043, whose global-session changes only drop NOT NULL on `plan_sessions.project_id` and `runs.project_id`.

Runner protocol 4 distinguishes these jobs from protocol 3, so an older runner cannot receive a global turn and try to fetch an empty repository.

Global PM turns use a stable empty directory under the runner's `sessions/<sessionId>`, without fetching a repository or creating a Git worktree. They use the default PM instructions, not project role overrides or a project brief. The prompt tells the PM to start a project thread to read code. Project sessions retain their read-only default-branch checkout.

Project-scoped PM tools accept a `project` slug: `list_tasks`, `get_task`, `get_run_outcomes`, `get_attachment`, `get_design`, `propose_plan`, `flag_stale_docs`, `delete_task`, `create_task`, `update_task`, `move_task`, `approve_task`, and `update_epic`. Global sessions must supply it; project sessions default to their own project and may name another. The shared server resolver applies equally to attachment/design reads. `ask_question` and `approve_plan` act on the conversation itself and need no project argument. The direct tools in `pmDirectTools` and `delete_project`, `stop_run`, `stop_all` and `resume_all` act on Corral as a whole or name their own target, so they work the same in both kinds of session; their audit entries have no project when the call has none and the session is global. Approval continues to use the plan's own project and the human's post-proposal message.

A conversation can plan for a different project after its current plan is approved or discarded. It cannot revise one project's pending plan into another project's plan; the tool asks to resolve the current plan first. Closing a session discards only its own Drafts, including Drafts created for projects other than the session's default. Global replies and questions appear in the Inbox with Global in place of a project name; global runs remain visible in run history. Factory-tool Activity also resolves the surviving session: a session with no project is labelled Global and keeps its PM conversation link. A deleted session has no conversation link; entries without a surviving project or global session retain the Removed project label.

Verification: `apps/server/src/plan-global.test.ts` exercises real HTTP and fenced runner WebSocket calls, the migration preserving a pre-existing conversation, project defaults and overrides, missing-project errors, global Inbox/run visibility, and follow-up turns. Runner tests check the actual process working directory and instructions, plus the absence of a Git checkout.
