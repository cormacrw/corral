# Stable page instances across selections

Inbox, global Settings, Plan session and task pages set a constant `definePageMeta` key. Agent pages key on the agent name, so changing the run keeps the runs list while changing agent creates a new page. Project routes retain Nuxt's default keys.

Inbox keeps its tab, search, task visibility and list scroll across item selection. Task-to-task clicks and auto-advance after an action go through `itemRoute`, which preserves the task query so the flyout stays mounted. An action's item can leave the list before its response arrives, because Resolved rows have their own ids, so `actingOn` stops the `selected` watcher closing the flyout in that gap. The detail scrollers and `InboxReleaseNotes` are keyed by item, so the next item opens at its top with no error or busy state left over. Reply text, composer attachments, retry destination and human checklist belong to the selected item; evidence responses from a previous selection are ignored. Live refreshes of the same item preserve the reply draft. A send finishing for an older selection cannot clear the new reply or advance the new selection.

Selecting an Inbox item makes no `GET /api/inbox`, even when it is unread. `POST /api/plan/sessions/:id/read` publishes `plan.session` with `markedRead: { inboxCount }` and `POST /api/deployments/:id/read` publishes `deployment.updated` with `markedRead: true`. Those events skip Inbox invalidation in `queries/dependencies.ts` and refetches in the Inbox page, which patches the row with `markRead`. Plan read events also write the server count into the cached Inbox for the shell. Like the server, it drops a thread listed only for its unread reply, keeps a read release note, and reapplies the read over any load that was in flight.

TaskDetail clears its editing fields, confirmation, attachments and loaded data and returns to its default tabs on task-ref changes, and ignores responses for previous tasks, including saves, status changes, resume, place, comments and delete. `applyTask` is the one place an action's response becomes `task`, because slug and number derive from it. DesignReview is keyed by task. PlanConversation clears its reply, attached task and composer attachments when the session changes; a one-tap answer finishing in the previous session cannot restore its draft into the new thread. Agent run selection clears the transcript and ignores an older request that finishes after the selection changes. On desktop and mobile the transcript scroller and `RunComposer` are keyed by run, so scroll, expanded steps and a mid-run draft stay with their run.

These keys are the interim fix ahead of Inbox, Settings and agent nested routes. Parent/child routing should preserve these state boundaries when it replaces the keys.
