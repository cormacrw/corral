# Stable page instances across selections

Inbox, Plan session and task pages set a constant `definePageMeta` key. Agent pages use nested routes instead: `pages/agents/[name].vue` holds the header, stats and runs list under Nuxt's default key, so changing the run keeps them while changing agent creates a new page. Its `<NuxtPage>` renders the transcript child `[name]/[[runId]].vue` with `useAgentRuns`' `view` as a prop. The child sets a constant `definePageMeta` key: its panes key themselves by the selected run, so reaching the auto-selected run by URL keeps its draft, and Nuxt's router plugin only updates the layout's route after a same-child navigation when that key is unchanged (without it the phone tab bar stays hidden after Back). On a phone the parent shows `MobileAgent` or the child, never both. Project routes retain Nuxt's default keys.

Inbox keeps its tab, search, task visibility and list scroll across item selection. Task-to-task clicks and auto-advance after an action go through `itemRoute`, which preserves the task query so the flyout stays mounted. An action's item can leave the list before its response arrives, because Resolved rows have their own ids; the held list (see [query-layer.md](query-layer.md#inbox)) keeps it selected through that gap, so the flyout stays open. The detail scrollers and `InboxReleaseNotes` are keyed by item, so the next item opens at its top with no error or busy state left over. Reply text, composer attachments, retry destination and human checklist belong to the selected item; evidence is keyed by the selected task. Live refreshes of the same item preserve the reply draft. A send finishing for an older selection cannot clear the new reply or advance the new selection.

Selecting an Inbox item makes no `GET /api/inbox`, even when it is unread. `POST /api/plan/sessions/:id/read` publishes `plan.session` with `markedRead: { inboxCount }` and `POST /api/deployments/:id/read` publishes `deployment.updated` with `markedRead: true`. Those events skip Inbox invalidation in `queries/dependencies.ts` and patch the cached row with `inboxWithRead`. Plan read events also write the server count into the cached Inbox for the shell. Like the server, it drops a thread listed only for its unread reply, keeps a read release note, and `inboxQuery` reapplies the read over any load that was in flight.

TaskDetail clears its editing fields, confirmation, attachments and loaded data and returns to its default tabs on task-ref changes, and ignores responses for previous tasks, including saves, status changes, resume, place, comments and delete. `applyTask` is the one place an action's response becomes `task`, because slug and number derive from it. DesignReview is keyed by task. PlanConversation clears its reply, attached task and composer attachments when the session changes; a one-tap answer finishing in the previous session cannot restore its draft into the new thread. Agent run selection clears the transcript and ignores an older request that finishes after the selection changes. On desktop and mobile the transcript scroller and `RunComposer` are keyed by run, so scroll, expanded steps and a mid-run draft stay with their run.

Settings uses nested routes: `pages/settings.vue` holds the section navigation, and Profile, Agents, Runners and Appearance own their content and queries. The index shows Profile on desktop and the section list on mobile; unknown single sections retain the shell with empty content. Only Agents and Runners observe the stale-on-mount CLI query, so opening either scans without a section watcher or stable page key.

Inbox keys remain an interim fix ahead of nested routes. Parent/child routing should preserve these state boundaries when it replaces the keys.
