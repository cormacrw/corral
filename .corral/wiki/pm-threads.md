# PM threads (COR-243)

The PM has five direct, audited tools in `pmDirectTools`: `start_thread`, `list_threads`, `read_thread`, `message_thread` and `close_thread`. They call the same PlanService methods as the existing session routes. The runner registers their shared schemas automatically; fenced PM tool calls supply the sender session from the live run, never caller input.

`start_thread` takes title, message, optional project slug and optional runtime. Omitting project creates a Global session, even when the sender is in a project. The chosen title is preserved. A child stores `parentSessionId`; its first message has role `thread`, senderSessionId and a snapshot senderTitle. Ordinary human messages retain role `human`. These are nullable additive columns in migration 0037; deleting a sender clears its link but preserves its name and agent attribution.

`list_threads` includes open and closed sessions across projects, with project slug (null for Global), parent, status, closed and running/activeRunId. `read_thread` takes threadId and a limit (default 20, maximum 100), returning messages latest first. `message_thread` takes threadId and message, starts a new PM turn and reopens a closed session. Like the human message route, it refuses a session with a queued or running turn; callers can read its progress and try after it finishes. `close_thread` uses the existing close service: stop the turn, discard pending plans and owned Drafts, and leave it closed until a human or agent messages it again. Run insertion locks and rechecks the session, and close stops any turn inserted before its close lock, so a delayed first turn cannot start after closing.

Every child turn ending saves a short `thread` notification naming it in its parent's history, with SSE updates and unread state. A notification does not reopen a closed parent, start a turn or clear its pending human question. Warm CLI sessions receive the saved notifications with their next turn's prompt; cold sessions also receive attributed conversation history. Agent messages cannot count as the human's plan approval. Parent and child links in Plan include closed children. Thread messages and notifications show the sending thread's title and link, on desktop and mobile.

`apps/server/src/pm-threads.test.ts` exercises HTTP and fenced runner WebSocket calls for delegation, runtime, Global scope, cross-project listing, newest-first limits, attribution, completion, warm notification replay and close/reopen. Evidence can be captured with CORRAL_THREAD_EVIDENCE when invoking the test directly.
