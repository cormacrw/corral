# PM threads (COR-243)

The PM has five direct, audited tools in `pmDirectTools`: `start_thread`, `list_threads`, `read_thread`, `message_thread` and `close_thread`. They call the same PlanService methods as the existing session routes. The runner registers their shared schemas automatically; fenced PM tool calls supply the sender session from the live run, never caller input.

`start_thread` takes title, message, optional project slug and optional runtime. Omitting project creates a Global session, even when the sender is in a project. The chosen title is preserved. A child stores `parentSessionId`; its first message has role `thread`, senderSessionId and a snapshot senderTitle. Ordinary human messages retain role `human`. These are nullable additive columns in migration 0037; deleting a sender clears its link but preserves its name and agent attribution.

`list_threads` includes open and closed sessions across projects, with project slug (null for Global), parent, status, closed and running/activeRunId. `read_thread` takes threadId and a limit (default 20, maximum 100), returning messages latest first. `message_thread` takes threadId and message, starts a new PM turn and reopens a closed session. Like the human message route, it refuses a session with a queued or running turn; callers can read its progress and try after it finishes. `close_thread` stops and closes a thread only when there is no proposed plan or owned Drafts to discard. Otherwise it refuses and tells the PM to ask the human to use Close thread and confirm the discard (D11/D27). The close service checks this before stopping and again under the session lock; the human route retains its confirmed discard behavior. A human or agent message reopens an empty closed thread. Run insertion locks and rechecks the session, and close stops any turn inserted before its close lock, so a delayed first turn cannot start after closing.

Every child turn ending saves a short `thread` notification naming it in its parent's history, with SSE updates. Completed, failed, explicitly stopped, closed, kill-switch-stopped and otherwise interrupted child turns (including runner restart) all notify; repeated runner exits do not duplicate the notice. Notices leave the parent’s human unread flag unchanged, so a read parent never returns to the Inbox with an old reply. A notification does not reopen a closed parent, start a turn or clear its pending human question. Warm CLI sessions receive only notices since the preceding turn’s input message, so a later turn does not replay notices already delivered. Notices arriving during a turn remain available for its next turn. The action-result ledger is still replayed in full; cold sessions receive attributed conversation history. Successful thread actions are audited under the target project, including null for a Global target rather than the sender’s project. Agent messages cannot count as the human's plan approval. Parent and child links in Plan include closed children. Thread messages and notifications show the sending thread's title and link, on desktop and mobile.

`apps/server/src/pm-threads.test.ts` exercises HTTP and fenced runner WebSocket calls for delegation, runtime, Global scope, cross-project listing, newest-first limits, attribution, completion, warm notification replay and close/reopen. Evidence can be captured with CORRAL_THREAD_EVIDENCE when invoking the test directly.
